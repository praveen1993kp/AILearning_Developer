# Copilot Instructions

Purpose
-------
This document guides the Co-pilot side chat (developer assistant) for generating, editing, and debugging code for the `resume-search-rag` project. Use these instructions to produce safe, testable, and production-ready TypeScript/Express code that follows the architecture in `Architecture.md`.

How to use
----------
- Read `Architecture.md` and the prompts in this folder before implementing a feature.
- When asked to implement an endpoint/service: produce focused patches, wire tests, and provide a short changelog.

Developer rules
---------------
- Use TypeScript with explicit types for public interfaces.
- Keep changes minimal and atomic; avoid unrelated refactors.
- Validate inputs and return structured JSON errors with `requestId` and `errorCode`.
- Avoid logging raw PII; mask emails/phones in logs and examples.

Testing
-------
- Add unit tests for business logic in `src/services` (use `jest` or `vitest`).
- Add a small integration test for health endpoints by starting the Express app on a random port.

Prompts
-------
- Use the domain-specific prompts in this folder when calling the LLM from `LLMService`.
- Each prompt file contains: role, input schema, desired JSON output schema, constraints, and examples.

Error handling patterns
-----------------------
- External failure: return `5xx` with `errorCode`, `message`, and `requestId`.
- Client validation: return `4xx` with a helpful `error` and `details` array.

Deliverables for feature work
-----------------------------
1. Small, focused patch implementing the feature.
2. Unit tests covering core logic.
3. Updated prompts or examples if the API contract changed.
4. A one-line summary of files changed and why.

If you need clarification about the public payload or default limits, ask the user before making breaking changes.

Keep messages concise. When producing patches: include file list, brief reason, and test plan.
# GitHub Copilot Instructions for Resume Search Algorithm Development

## Overview
This document provides instructions for using GitHub Copilot effectively while developing the Resume Search Algorithm using the RAG (Retrieval-Augmented Generation) approach. It includes tips for generating, editing, and debugging code related to the various components of the project.

## Getting Started with GitHub Copilot
1. **Installation**: Ensure that the GitHub Copilot extension is installed and enabled in your code editor.
2. **Sign In**: Sign in with your GitHub account to activate Copilot.

## Using Copilot for Code Generation
- **Contextual Suggestions**: As you type comments or function names, Copilot will suggest code snippets based on the context. Use descriptive comments to guide Copilot in generating relevant code.
  
  Example:
  ```typescript
  // Function to generate embeddings using Mistral API
  ```

- **Prompting for Specific Functions**: If you need a specific function, start typing the function name followed by a comment describing its purpose. Copilot will provide suggestions.

  Example:
  ```typescript
  // Function to perform BM25 search
  function bm25Search(query: string, filters: object) {
  ```

## Editing and Refining Code
- **Accepting Suggestions**: Use the `Tab` key to accept a suggestion from Copilot. If the suggestion is not what you need, continue typing to refine it.
- **Iterative Development**: Generate code in small increments. After accepting a suggestion, test it before moving on to the next piece of functionality.

## Debugging with Copilot
- **Error Handling**: If you encounter errors, you can ask Copilot for help by typing comments that describe the issue or the expected behavior.
  
  Example:
  ```typescript
  // Fix the error in the LLM re-ranking function
  ```

- **Refactoring Suggestions**: If you want to improve or refactor existing code, provide comments that describe the desired changes. Copilot can suggest alternative implementations.

## Best Practices
- **Use Descriptive Comments**: The more context you provide, the better Copilot can assist you. Use comments to describe the purpose of functions, parameters, and expected outputs.
- **Review Generated Code**: Always review the code generated by Copilot for correctness and adherence to project standards.
- **Collaborate with Team Members**: Share Copilot-generated code with your team for feedback and improvements.

## Conclusion
By following these instructions, you can leverage GitHub Copilot to enhance your productivity while developing the Resume Search Algorithm. Use it as a collaborative tool to generate, edit, and debug code efficiently.
